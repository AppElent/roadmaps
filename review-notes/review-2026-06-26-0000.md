## Action Items

### Major

- [ ] **Archived roadmaps are unreachable**
  - **What:** Archiving a roadmap from the card menu removes it from the list with no way to view, find, or unarchive it afterward.
  - **Where:** `/roadmaps` → [src/routes/roadmaps/index.tsx](../src/routes/roadmaps/index.tsx) (calls `api.roadmaps.archive` with `{ archived: true }`, lists via `api.roadmaps.list`) and [src/components/roadmaps/RoadmapCard.tsx](../src/components/roadmaps/RoadmapCard.tsx) (Archive button)
  - **Type:** feature gap
  - **Fix direction:** Add a way to view archived roadmaps — e.g. a "Show archived" toggle/tab on `/roadmaps` that calls `api.roadmaps.list` with an `archived: true` filter (check the Convex query signature in `convex/roadmaps.ts` and add the filter arg if missing), and an "Unarchive" action (reuse `api.roadmaps.archive` with `{ archived: false }`) surfaced on archived cards instead of Duplicate/Archive.
  - **Acceptance:** After archiving a roadmap, the user can navigate to a view that lists it, and can unarchive it from there, after which it reappears in the normal roadmaps list.

- [ ] **Modals have no visible close icon**
  - **What:** None of the app's dialogs show a close (X) icon. The only ways to close are Escape, clicking the backdrop, or an in-content action button — not discoverable.
  - **Where:** All Radix `Dialog`-based modals: [src/components/fields/FieldManager.tsx:59](../src/components/fields/FieldManager.tsx), [src/components/lanes/LaneManager.tsx](../src/components/lanes/LaneManager.tsx), [src/components/milestones/MilestoneManager.tsx](../src/components/milestones/MilestoneManager.tsx), [src/components/roadmaps/RoadmapSettingsDialog.tsx](../src/components/roadmaps/RoadmapSettingsDialog.tsx), [src/components/share/ShareDialog.tsx](../src/components/share/ShareDialog.tsx), [src/components/diagrams/DiagramShareDialog.tsx](../src/components/diagrams/DiagramShareDialog.tsx), [src/components/diagrams/CreateDiagramDialog.tsx](../src/components/diagrams/CreateDiagramDialog.tsx), [src/components/roadmaps/CreateRoadmapDialog.tsx](../src/components/roadmaps/CreateRoadmapDialog.tsx), [src/components/io/ImportExportDialog.tsx](../src/components/io/ImportExportDialog.tsx), [src/components/versions/VersionDialog.tsx](../src/components/versions/VersionDialog.tsx)
  - **Type:** UX
  - **Fix direction:** Add a shared close-button (Lucide `X` icon, top-right of the dialog header) wrapped in Radix `Dialog.Close`, ideally as one reusable piece (e.g. a small wrapper or shared header component) so each of the 10 dialogs gets it consistently rather than copy-pasted 10 times.
  - **Acceptance:** Every listed modal shows a clickable X in the top-right corner that closes it, in addition to existing Escape/backdrop-click behavior.

### Minor

- [ ] **"Start planning" button text isn't white**
  - **What:** The CTA button has `text-white` in its class but the rendered text doesn't appear white — looks like a color override or contrast issue.
  - **Where:** `/` (landing page) → [src/routes/index.tsx:63](../src/routes/index.tsx) — `<a>` with class `rounded-full bg-[var(--palm)] px-6 py-2.5 text-sm font-semibold text-white ...`
  - **Type:** bug
  - **Fix direction:** Inspect computed styles on the live element to find what's overriding `text-white` (a more specific selector, a CSS variable resolving wrong, or an ancestor `color` rule winning via specificity/ordering). Fix so the intended white text actually renders.
  - **Acceptance:** "Start planning" button text renders as solid white against the `--palm` green background.

- [ ] **Dark mode inconsistent across the app**
  - **What:** Switching to dark mode doesn't apply consistently everywhere — e.g. on `/account`, the page shell/background stays light while the profile/security/appearance panels render in a dark theme using `--auth-*` CSS variables, producing a mixed light/dark page.
  - **Where:** `/account` → [src/routes/account/index.tsx](../src/routes/account/index.tsx) (panels use `bg-[var(--auth-field-bg)]`, `text-[var(--auth-fg)]`, etc., which appear hardcoded to a dark palette regardless of the `.light`/`.dark` class set on `<html>`)
  - **Type:** bug
  - **Fix direction:** Check whether `--auth-*` variables are defined per-theme in `src/styles.css` alongside the `.light`/`.dark` selectors used elsewhere (per CLAUDE.md theming convention), or whether they're hardcoded to dark values only. Align the account page's theme tokens with the rest of the app's light/dark variable scheme.
  - **Acceptance:** Toggling Light/Dark/Auto in the appearance section consistently re-themes the entire `/account` page (background, panels, text) to match the rest of the app, with no mixed light/dark regions.

- [ ] **Roadmap card click target doesn't cover the full card**
  - **What:** Clicking in the lower portion of a roadmap card (below the title/meta text, but still within the card's hover-highlighted bounds) doesn't open the roadmap, even though the hover state visually suggests the whole card is clickable.
  - **Where:** `/roadmaps` → [src/components/roadmaps/RoadmapCard.tsx](../src/components/roadmaps/RoadmapCard.tsx) — likely the `onOpen` click handler is bound to a `<button class="text-left">` that doesn't span the same area as the hover-styled container `div.group`.
  - **Type:** bug
  - **Fix direction:** Make the clickable element's bounding box match the hover-highlighted container exactly (e.g. move the click handler/button to wrap the same area as the `group` hover styles, or size the inner button to fill its parent).
  - **Acceptance:** Clicking anywhere within the visually-highlighted card area (on hover) opens the roadmap; there's no dead zone.

- [ ] **Dependency-link drag affordance is unintuitive and conflicts with resize**
  - **What:** The drag-to-link gesture for connecting two timeline items (creating a dependency) is confusing to discover/use, and its hit area overlaps with the item bar's resize handle, making it easy to trigger one when meaning the other.
  - **Where:** Roadmap editor timeline (`/roadmaps/$id`, Timeline tab) → [src/components/timeline/DependencyLayer.tsx](../src/components/timeline/DependencyLayer.tsx), interacting with item bars rendered in [src/components/timeline/TimelineView.tsx](../src/components/timeline/TimelineView.tsx)
  - **Type:** UX
  - **Fix direction:** Give the dependency-link handle a distinct, separated hit area from the resize handle (e.g. a small dedicated connector knob at the edge of the bar, only shown/active on hover, visually distinguishable from the resize cursor region) so dragging to link vs. dragging to resize aren't ambiguous at the same screen position.
  - **Acceptance:** A user can resize an item bar and separately drag a connector to link it to another item without the two gestures interfering or being mistaken for each other.

### Nice-to-have / Ideas

- [ ] **Timeline column widths don't adapt well at the extremes**
  - **What:** When there are few visible columns (e.g. Quarter zoom showing only Q1–Q4), columns stay narrow and leave excess unused whitespace in the timeline grid instead of stretching to fill the available width. When there are many columns, they could be packed a bit tighter than they currently are — bounded only by keeping header labels (e.g. "JAN", "Q1") fully readable without truncation or overlap.
  - **Where:** Roadmap editor timeline (`/roadmaps/$id`) → column width logic in [src/lib/timeline.ts](../src/lib/timeline.ts) (`columnWidth(zoom)`, used to compute `axisWidth = periods.length × columnWidth(zoom)`) and rendering in [src/components/timeline/TimelineView.tsx:190-197](../src/components/timeline/TimelineView.tsx) / [src/components/timeline/TimeAxis.tsx](../src/components/timeline/TimeAxis.tsx)
  - **Type:** design
  - **Fix direction:** When the computed `axisWidth` is less than the available container width and the period count is small, stretch column widths to fill the container instead of leaving whitespace. When period count is large, allow `columnWidth(zoom)` to shrink further than its current floor, as long as the header label text in `TimeAxis.tsx` still fits without clipping/overlap (test against the longest label per zoom level, e.g. "SEP" or "Q4").
  - **Acceptance:** At low column counts, the timeline grid visually fills the available width with no large empty gap. At high column counts, columns are noticeably tighter than today while every header label remains fully readable (not clipped or overlapping).
